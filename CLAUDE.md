## Project Blueprint
_Generated by project-discovery v1 from docs/ROADMAP.md. Re-run to re-sync._

- **Product:** DevFest Tacna 2026 "DevFest Space Arcade · Odisea de Código" (roadmap working name: G-App / Interfaz de Mando): event companion web app with galactic-exploration gamification (QR scanning, ranks, XP, G-Credits, leaderboard); model: internal/event; key metric: QR check-ins per cadet
- **Actors:** Cadet (attendee, authenticated via existing account, picks alias; in phase 5 plays mini-games and builds a contact network by scanning other cadets); Staff (authenticated, scans catering QR); Admin/Organizer (authenticated, issues ephemeral QRs, controls stage leaderboard, defines and maintains squads in phase 2, missions, quadrants, venue map stands and narrative communications in phase 3, helped by AI suggestions, economy, squad prizes, food gates and badges in phase 4, enabled mini-games per edition in phase 5)
- **Stack profile:** next-firebase
- **Stack:** framework Next.js (TypeScript strict), backend/db Firebase (Firestore + Cloud Functions), auth Firebase Auth (social login), styling/ui Tailwind + shadcn/ui (strategy confirmed in shadcn-ui-designer), deploy TBD
- **Integrations:** Device camera / QR scanning (phase 2); venue map drawn by the app from edition data (phase 3); AI model for admin mission suggestions (phase 3, provider decided in that module); arcade mini-games (phase 5); secrets server-side only
- **Surfaces:** mobile-first authenticated cadet dashboard (zero-download web link), QR scanner, missions and map tabs (phase 3), Logros tab (phase 4), mini-game screens after a completed mission and the Red (contacts) screen with the cadet's contact card (phase 5), staff checkpoint view, admin panel (phase 2: team, QR, Puestos, squads, event; phase 3: missions, quadrants, map, communications; phase 4: Economía, squad credits, Logros; phase 5: Mini-juegos), full-screen stage leaderboard HUD (phase 6)
- **Cross-cutting:** i18n one language (UI copy in Spanish; code, identifiers, variables, comments and tests in English), testing unit + e2e, payments none, analytics TBD (key metric: check-ins), realtime needed in phase 6 (leaderboard; the phase 2 ephemeral QR shipped stateless without realtime)
- **Phases:** 1 Cadet Access & Initialization | 2 Jump Scanner & Logistics Checkpoints (incl. admin-managed squads) | 3 Active Missions & Galactic Quadrants (incl. admin missions, default set, AI suggestions, venue map) | 4 Rank, G-Credits & Supplies | 5 Mini-games & Cadet Network | 5.5 Real-world testing & UI/UX adjustments | 6 Final Deployment & Leaderboard | 7 Virtual store (future, not scheduled; may be a separate app) (source of truth: docs/ROADMAP.md)
- **Current phase:** 5.5 Real-world testing & UI/UX adjustments (phase 6 Final Deployment & Leaderboard closed in code 2026-10-11; pending from it: running the load test on a test project and choosing App Hosting or Vercel, see docs/deploy.md). Phase 5.5 Real-world testing & UI/UX adjustments (added by the organizer 2026-10-10: the integrated test plus a redesign pass on the screens the organizer flags; feedback is captured screen by screen in the Bitácora de ajustes artifact https://claude.ai/artifact/HM8bFpmCTtgjJuNRzgt8kt). Previous: 5 Mini-games & Cadet Network (phase 1 closed 2026-10-09; phases 2 and 3 closed in code 2026-10-09; phase 4 closed in code 2026-10-10; phase 5 closed in code 2026-10-10; next: the integrated check against real Firebase, an admin session, phones and Gemini, moved by the organizer to right after phase 5)
- **Current phase modules:** 1 Ranking core (cadets by edition XP, squads by members' total XP, a cadet's place and the top 10 in the app) | 2 Stage state and admin "Escenario" (pause, freeze, view cadets/squads/both, champions' reveal; audited) | 3 Stage HUD /escenario in real time on the projector (admin session) | 4 Raffle (every G-Credit earned in the edition is a ticket, not spent; admin minimum, 1 by default; prizes and draws in the app shown on the big screen; a winner never repeats) | 5 Load and deployment readiness (300 attendees, test with 600; App Hosting or Vercel decided at the end). Phase 5.5 modules, open in parallel: integrated test setup, review pass in the Bitácora de ajustes, adjustments module by module
- **Prepare-early constraints:** participant doc (per edition, under `events/{eventId}`) with alias, squad, xp, credits and `attendedAt`; role (attendee|staff|admin) is a global custom claim; rank is derived from xp via a configurable ladder; XP/credits/QR validation only via server (Cloud Functions/rules), never client-trusted; idempotent per cadet+checkpoint records; leaderboard via aggregated/cached reads for mass load (phase 6); squad ids are stable slugs read through a catalog port, and retiring a squad never deletes cadet profiles or aggregates (squad pot and leaderboard depend on them); phase 3: every XP change goes through a server-only ledger keyed per attendee+source (phase 4 economy and credits build on it), missions and quadrants have stable ids and are deactivated never deleted, mission types are a closed set validated by the server (a new type needs code); missions carry an optional `minigame` slot (empty until phase 5) and the ledger keeps the mini-game bonus as its own source, because mini-games are a bonus on a mission (win doubles its XP, loss keeps the base), not a mission type; phase 5 builds about 5 mini-games that the admin enables or disables per edition and assigns to missions
- **Constraints:** User-facing UI text in Spanish; all code, variable/type/file names, comments and tests in English; out of scope in phase 5: leaderboard and raffle sync (phase 6), the virtual store (phase 7); phase 5 (chosen 2026-10-10): mini-game results are trusted from the phone (arcade reflex games allowed), but the server issues the play ticket, accepts one result per mission and only for a completed mission whose mini-game is enabled; one attempt per mission, offered after completing it; winning doubles only the XP (not G-Credits); networking shares alias, squad and optional links (LinkedIn, GitHub, web) the cadet opts into, never email or private data; contact rewards are capped per edition and paid once per pair to both cadets; phase 4: G-Credits live in a global wallet (`wallets/{uid}` with a ledger of credits and debits, each entry tagged with its edition) so a future store can spend them; squad credits are a separate per-edition currency only redeemed for admin-defined prizes; food gates have no restriction by default (2026 coffee break needs no level), badge rule types are a closed set the server evaluates (an admin badge picks one and its parameters); AI suggestions never publish by themselves; the venue map is fictional for 2026 and replaceable per edition; quiz: two attempts, the second gives half the XP; default XP per type talk QR 50, stand 30, quiz 40, keyword 40 (editable per mission); keyword: unlimited attempts behind a rate limit; AI suggestions: Gemini free tier (chosen 2026-10-09); communications: each one unlocks when a specific mission is completed, or is open from the start (chosen 2026-10-09); theme dark navy/purple with neon cyan/lime accents (formalized by design-wizard)

## Design System
_Generated by design-wizard v2. Re-run the wizard to change it._

- **Product:** B2C-style event audience (conference attendees), playful and futuristic tone; "DevFest Space Arcade · Odisea de Código", a 90s arcade reinterpreted as a modern 2026 PWA (70% modern UI / 30% 16-bit pixel art)
- **Preset / direction:** Custom (Space Arcade), close to Neon HUD as reference
- **Palette (dark):** background #0a0f24, surface #111833, foreground #f4f6ff, muted #b4bde0, border #232c57, primary #22d3ee, on-primary #04121a, accent #a3e635, destructive #fb7185
- **Typography:** display Space Grotesk, body Inter, mono none (pixel accent: Tiny5, only for game tags like "+100 XP", "XP x2", "NV 3" and at most one callout per screen)
- **Surface style:** neon-hud
- **Shape & density:** radius lg (20px; md 14px for buttons/mission cards, sm 10px for chips, pill for chips/progress), density comfortable
- **Theme:** default dark (dark only); dynamic theming yes; tokens are CSS variables mapped to Tailwind semantic colors
- **Motion:** expressive; Framer Motion yes; reduced-motion respected (`useReducedMotion` / `prefers-reduced-motion`)
- **Platform:** mobile-first extreme (single column up to 520px, 48px touch targets, bottom nav, safe-area insets; side rail from 760px); PWA yes
- **3D:** none
- **Constraints:**
  - Extra tokens: bg-deep #050816, bg-violet #150f38, surface-raised #18214a, line-strong #5b6ab8 (control borders, 3.79:1), text-subtle #8f9ac4 (metadata), cyan/violet/magenta/lime/gold accents, violet-soft #b9a3ff (violet as text). Spacing space-1..8 (4,8,12,16,20,24,32), radius and shadow/glow tokens as in docs/DESIGN-SYSTEM.md.
  - Contrast verified (WCAG 2.1): all text pairs pass; border #232c57 is decorative (1.42:1), use line-strong for controls. `violet #8b5cf6` is fill/border only (4.48:1 with on-accent); text violet uses violet-soft. Text on cyan/lime/gold fills uses on-accent.
  - Glow (glow-cyan/magenta/gold) on a single element per screen. Translucent panels (jump scene, bottom nav) need a solid fallback without `backdrop-filter` and contrast checked on the real background.
  - Pixel art only for avatar, ship, planets, medals, enemy, coin, star; never for paragraphs, titles, buttons or card frames. Integer scales (16px to 32/48/64), `shape-rendering: crispEdges`. Official logos come from the brand kit, not redrawn, with one exception approved on 2026-10-05: the event squads (Angular, Firebase, Gemini) use 16x16 pixel-art renditions of their symbol (never the wordmark), drawn by hand over the silhouette and colors of the official mark and kept as squad data. The organizer is responsible for confirming brand-usage permission for these renditions.
  - UI icons are line icons; pixel art is never a UI icon.
  - Voice (Spanish copy): cadet, XP Estelar, Créditos de Galaxia, planets (Google Cloud, Firebase, Android, AI, Comunidad GDG), missions, hyperspace jump = QR scan. Ranks: Recluta (0 XP) → Piloto (100) → Comandante (500) → Leyenda Estelar (2000). Buttons start with a verb in sentence case ("Escanear QR", "Ver mapa", "Reclamar recompensa"). Mini-game rewards only (win = XP x2, loss keeps base XP).
  - Reference implementation `window.SpaceArcade` (React 18 global) is not in the repo: components must be re-implemented in Next.js/TypeScript following the tokens and props in the document.
  - Phase scope: design covers screens from later phases (map, achievements, mini-game); only build what the Current phase needs.
- **Source:** designsystem.md (docs/DESIGN-SYSTEM.md)
